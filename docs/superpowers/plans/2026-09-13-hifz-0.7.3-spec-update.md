# Quran Hifz 0.7.3 Specification Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the validated corpus bootstrap, dual anchoring protocols, dynamic schedule, calendar promotion, differentiated consolidation actions, French UI, raw measurements, and provisional speed calibration on Quran Hifz 0.7.3-boox.

**Architecture:** Keep Android persistence and rendering in `hifz-app`, but move decision rules into small deterministic policy classes so the new state transitions can be unit-tested without an Android device. Schema v4 performs one atomic migration from v3, preserves unrelated progress, and initializes the 49:1–114:6 reconstruction range as promoted-but-pending. Runtime session code consumes policy results and persists each repetition or queue mutation synchronously.

**Tech Stack:** Android Java, Kotlin/JVM domain core, SharedPreferences, org.json, JUnit 4, Gradle Android plugin.

**Spec:** `quran-hifz-specification-mise-a-jour (1).txt` supplied for this mission, plus the approved audit adjustments dated 2026-09-13.

> **2026-09-13 final protocol override:** Reconstruction Ancrage is **35 repetitions = 20 visible + 5 at 50% + 5 at 75% + 5 at 100%**, with **no 25% stage**. This supersedes the earlier 25- and 30-pass reconstruction variants in source notes and prior iterations.
