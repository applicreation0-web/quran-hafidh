# Quran Hifz 0.7.1 Official Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the official Quran Hifz BOOX update after the 0.7 cosmetic audit, with reader/reveal, masking, Tafsir UI/packaging, metadata and release-signing defects fixed without changing Mushaf content or Hifz semantics.

**Architecture:** Keep the existing offline WebView-based Mushaf renderer and native Activities. Fix the reader contract at the JS/CSS/native bridge boundary, keep Tafsir fully local, normalize its asset packaging, and produce one release APK for package `com.quransafeguard.hifz`. Audio remains an external local pack and is not bundled.

**Tech Stack:** Android Java/Kotlin, Gradle, WebView HTML/CSS/JS, SQLite/GZip local assets, GitHub Actions, apksigner.

**Spec:** User-approved defect list in the 2026-09-12 conversation plus `AUDIT-0.7-boox.md`.

## Global Constraints

- Do not modify the 604 Mushaf page payloads.
- Do not change Sabqi, Itqan, Murajaah, free memorisation, quotas, cursor or persistence semantics.
- Do not reimport or bundle the Husary audio ZIP.
- Keep `applicationId = com.quransafeguard.hifz`.
- Tafsir remains available only in Lecture/Study, never in memorisation interactions.
- BOOX/E-Ink updates must stay local and avoid decorative animations/full refreshes.
- Official update must use the existing durable Quran Hifz keystore and a versionCode greater than 7.
